**プロジェクト名**: AI薬局システムチェッカー PoC（Proof of Concept）  
**文書バージョン**: v1.0

## 1. 実験概要

### 1.1 目的

AIシステムを用いて調剤レセプト（月1,000枚規模）の加算漏れ・算定ミス・薬学的問題を自動検出し、以下を実証する。

- 技術的実現可能性の確認
- 回収漏れ点数の定量的測定
- 薬剤師の業務効率化効果の測定
- 製品化・販売に向けた実績データの取得

### 1.2 実験期間

| フェーズ | 期間 | 内容 |
|----------|------|------|
| Phase 1 | 1〜2ヶ月目 | 環境構築・データ準備・ルール設計 |
| Phase 2 | 3〜4ヶ月目 | AIチェック試験運用・精度検証 |
| Phase 3 | 5〜6ヶ月目 | 本格運用・効果測定・改善 |

### 1.3 対象

- 対象薬局: ケーファーマシー株式会社 全店舗（または指定店舗）
- 対象レセプト: 月1,000枚（調剤レセプト）
- 対象期間: 直近3ヶ月分の過去データ＋リアルタイム処理

## 3. データ管理・セキュリティ

### 3.1 取り扱いデータ

| データ種別 | 内容 | 機密度 |
|-----------|------|--------|
| レセプトデータ | 処方内容・点数・算定項目 | 極秘（個人情報含む） |
| 薬歴データ | 服薬指導記録・副作用歴 | 極秘（要配慮個人情報） |
| マスタデータ | 薬価・診療報酬点数表 | 公開情報 |
| 算定ルール | 加算要件・算定条件 | 内部情報 |

### 3.2 個人情報保護対応

- **匿名化処理**: レセプトの患者氏名・生年月日・保険者番号はハッシュ化または削除
- **仮名化**: 患者IDを内部管理IDに置換してから分析
- **データ保存場所**: 国内サーバー限定（クラウド使用時はAWS東京リージョン等）
- **アクセス制御**: 最小権限の原則。開発者は匿名化済みデータのみアクセス可
- **契約**: 秘密保持契約（NDA）・個人情報取扱委託契約を実験開始前に締結

### 3.3 セキュリティ要件

```
通信: TLS 1.3以上（全通信を暗号化）
保存: AES-256暗号化
認証: 多要素認証（MFA）必須
ログ: 全アクセスログを6ヶ月保管
監査: 月次セキュリティレビュー実施
```

### 4.2 技術スタック（PoC推奨）

| 層 | 技術 | 理由 |
|----|------|------|
| バックエンド | Python（FastAPI） | AI/ML連携が容易、開発速度が速い |
| AIエンジン | Python（pandas, scikit-learn） | PoC段階はルールベース中心 |
| データベース | PostgreSQL | 医療データの信頼性・ACID準拠 |
| フロントエンド | React + TypeScript | UIの柔軟性・保守性 |
| インフラ | AWS（東京リージョン） | 国内データ保管・FISC対応 |
| 認証 | Auth0 または AWS Cognito | MFA対応・実装コスト削減 |

## 5. チェック機能仕様

### 5.1 Phase 1で実装するチェック項目（コア機能）

#### カテゴリA: 加算漏れ検出（優先度：最高）

| チェックID | 項目 | 検出ロジック |
|-----------|------|------------|
| A-01 | 特定薬剤管理指導加算漏れ | ハイリスク薬（抗がん剤・抗凝固薬等）が処方されているが加算が算定されていない |
| A-02 | 吸入薬指導加算漏れ | 吸入薬が処方されているが加算が算定されていない |
| A-03 | 服薬管理指導料の区分誤り | 手帳あり/なし/オンラインの区分が状況と一致しないケース |
| A-04 | 重複投薬・相互作用防止加算漏れ | 疑義照会記録があるが加算算定なし |
| A-05 | 外来服薬支援料漏れ | 一包化実施時の算定漏れ |

#### カテゴリB: 算定ミス検出（優先度：高）

| チェックID | 項目 | 検出ロジック |
|-----------|------|------------|
| B-01 | 点数計算ミス | 薬剤料＝薬価×数量×日数で再計算し不一致を検出 |
| B-02 | 算定回数制限超過 | 月1回限り等の制限項目の重複算定 |
| B-03 | 旧点数適用 | 最新改定後も旧点数が適用されているケース |
| B-04 | 投与日数上限超過 | 向精神薬・麻薬等の投与日数制限チェック |
| B-05 | コメント記載漏れ | 算定理由コメントが必須の項目で記載がない |

#### カテゴリC: 返戻・査定リスク（優先度：中）

| チェックID | 項目 | 検出ロジック |
|-----------|------|------------|
| C-01 | 病名と薬剤の不整合 | 処方薬の適応症が傷病名に含まれていない |
| C-02 | 保険適用外用法 | 承認用法・用量を逸脱した処方 |
| C-03 | 過去査定パターン照合 | 審査支払機関の査定事例DBと照合 |

### 5.2 Phase 2以降で追加するチェック項目

- 在宅患者訪問薬剤管理指導料の算定漏れ
- 服用薬剤調整支援料の算定機会検出
- AI異常検知（過去データとの統計的乖離）
- 薬剤師別・処方医別のパフォーマンス分析

## 6. 評価指標（KPI）

### 6.1 技術的KPI

| 指標 | 目標値 | 測定方法 |
|------|--------|---------|
| 検出精度（Precision） | 85%以上 | 薬剤師による正誤判定 |
| 再現率（Recall） | 80%以上 | 手動チェックとの比較 |
| 処理速度 | 1,000枚/30分以内 | システムログ計測 |
| 誤検知率（False Positive） | 15%以下 | 薬剤師フィードバック |

### 6.2 ビジネスKPI

| 指標 | 目標値 | 測定方法 |
|------|--------|---------|
| 加算漏れ発見件数 | 月50件以上 | システム集計 |
| 回収増加点数 | 月5,000点以上 | レセプト提出前後の点数差 |
| 薬剤師チェック時間 | 手作業比50%削減 | 作業時間計測 |
| 返戻・査定件数 | 前月比30%削減 | 審査機関からの通知 |

### 6.3 ROI試算

```
月間回収増加点数:    5,000点以上（目標）
点数単価:            10円/点
月間回収増加額:      50,000円以上

薬剤師工数削減:      10時間/月
薬剤師時給換算:      3,000円/時間
工数削減効果:        30,000円/月

月次合計効果:        80,000円以上/月
```

## 7. 実施スケジュール

### Phase 1（1〜2ヶ月目）: 環境構築・データ準備

```
Week 1-2: 契約・セキュリティ設計
  ├── NDA・個人情報委託契約締結
  ├── セキュリティ要件の確定
  └── データフロー設計・承認

Week 3-4: データ準備
  ├── 過去3ヶ月分レセプトデータの匿名化
  ├── レセコンからのデータ出力形式確認
  └── 診療報酬マスタDB構築

Week 5-6: 開発環境構築
  ├── インフラ（AWS）セットアップ
  ├── バックエンドAPI基盤構築
  └── チェックルールエンジン実装（カテゴリA・B）

Week 7-8: 管理UI構築
  ├── ダッシュボード画面実装
  ├── アラート表示機能
  └── 薬剤師承認ワークフロー
```

### Phase 2（3〜4ヶ月目）: 試験運用・精度検証

```
Week 9-12: 並行運用
  ├── AIチェック結果と薬剤師手動チェックを並行実施
  ├── 週次で精度評価ミーティング開催
  ├── 誤検知パターンの収集・ルール改善
  └── カテゴリCチェック追加実装

Week 13-16: 精度改善
  ├── フィードバックデータで機械学習モデル調整
  ├── コメント自動生成機能の実装
  └── 処理速度最適化
```

### Phase 3（5〜6ヶ月目）: 本格運用・効果測定

```
Week 17-20: 本格運用
  ├── AIチェックを主、薬剤師確認を従に移行
  ├── 月次効果測定レポートの自動生成
  └── 診療報酬改定対応のルール更新プロセス確立

Week 21-24: 総括・製品化準備
  ├── 6ヶ月間のKPI集計・分析
  ├── 導入効果レポート作成（営業資料化）
  └── 製品版仕様策定・特許出願準備
```

## 8. リスクと対応策

| リスク | 発生確率 | 影響度 | 対応策 |
|--------|---------|--------|--------|
| データ漏洩 | 低 | 最大 | 匿名化徹底・暗号化・アクセスログ監視 |
| 誤検知が多く薬剤師の信頼を失う | 中 | 大 | Phase 1で精度目標を定め、下回ったら即改善 |
| レセコンとのデータ連携失敗 | 中 | 中 | 手動CSV出力を代替手段として準備 |
| 診療報酬改定への対応遅れ | 低 | 中 | 改定情報の定期モニタリング・更新プロセス設計 |
| 薬剤師の運用定着失敗 | 中 | 大 | 導入研修・操作マニュアル整備・週次フォロー |
